# FastUse — 果蝇式快计算机操作（P281-P283 架构生产实现）

**一条命令**：`python fastuse.py <url> "<自然语言目标>"` —— 自动规划、执行、验证网页操作。

## 架构（P281 设计的生产实现）

```
慢规划器（本地 7B）：自然语言目标 → 子目标序列
执行层：
  反射档（0 LLM）：唯一空输入框 + 目标点名值 → 直接填
  决策档（本地 7B）：压缩状态 → 动作 JSON 批量（带预测声称）
收费站（机械）：每步预测声称 vs DOM 真值逐字核验，REFUTED 计数入审计
```

## 实测指标（本地基准，P282/P285）

| 维度 | 截图循环（商业现状） | FastUse 实测 |
|---|---|---|
| 每步输入 | ~1100 token（截图） | **10-46 token（压缩状态）= 20-50 倍降** |
| 每步可验证性 | 无 | 预测声称机械核验（P270 循环） |
| 机械步延迟 | 秒-分钟 | **~260ms** |
| 端到端 | — | 登录→复选框→表单→报表 13 步全通（机械管线） |
| LLM 决策档 | — | 功能性运行，编排打磨中（见限制） |

## 用法

```bash
# 前置：本地 llama-server（端口 8499）加载 Qwen2.5-7B-Instruct Q4_K_M
python fastuse.py --local-site "在测试站完成任务：登录 admin/admin123，勾选 alpha 和 delta，提交"
python fastuse.py https://example.com "找到并点击第一个链接" --budget 30
```

- `--budget N`：最大动作步数（默认 60）
- `--report f.json`：结构化报告（步骤/声称精度/错误）
- `--screenshot-mode`：截图配对模式（对比实验用）

## 已验证的定律锚点

- 方向定律（P266）：压缩状态=方向信号，截图=量（20-50 倍 token 差实测）
- P270 坐标系教训：处理器直接给元素坐标（UIA/DOM），错位类错误被架构消灭
- P240 证据阶梯：压缩的带标签状态=可迁移证据层
- G6 边界：决策 LLM 对未见 UI 范式不会自发泛化——上报慢规划器是正解

## 诚实限制（当前版本）

1. **编排层打磨中**：子目标完成检测依赖执行模型的 done 判断与 done_when
   文本匹配——7B 模型的声称/完成判断质量不稳定（实测精度混合 1.0/0.0）；
2. **覆盖**：DOM 可访问性好的站点（表单/按钮/链接）效果最好；canvas/
   自绘界面退化为 OCR 兜底（未实现）；
3. **决策模型**：本地 7B 对复杂多步推理有限——更强模型（云端）可插拔
   （llm_url 参数），但需要订阅/key；
4. **蒸馏路线**：操作记录（fastuse_audit.jsonl + p282_distill.jsonl）持续
   累积，为未来本地小模型蒸馏储备示范数据。

## 文件
