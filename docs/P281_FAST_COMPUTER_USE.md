# P281：快计算机操作（Fast Computer Use）——果蝇式双层操作架构设计

**问题**：当前 computer use = 截图→思考→点击→截图→思考，token 浪费、速度慢。
**提案**：果蝇视觉式双层架构——机械感知处理器 + 专用点击 LLM + 慢规划器。

## 一、为什么这个架构是被我们自己的定律推导出来的

| 定律 | 对当前循环的判决 | 对新架构的规定 |
|---|---|---|
| 方向定律（P266） | 整帧截图=量（数千 token，信号≈零） | 帧间差+元素级结构=方向（该点哪、什么变了） |
| 标签悬崖（P240） | 纯视觉推理无方向反馈，原地打转（P270 实测 27/27 零命中） | 每步动作必须携带预测声称，机械验证后证据回传 |
| 证据阶梯（P248/Prop5） | 全屏重发=最贵的坏证据 | 压缩状态（UIA 树+差分）=可迁移的数值证据层 |
| P270 坐标系教训 | 模型坐标系≠屏幕坐标系，27 步全错 | **处理器直接给元素坐标**——错位类错误被架构消灭 |
| 域边界定律 | 无验证器的域门保持沉默 | UIA 树=机械真值源（元素存在性/状态可查） |

## 二、三层架构（果蝇映射）

```
慢规划器（DeepSeek，蘑菇体高端）：
  每几分钟一次：目标分解、子目标下发（"打开 X，填入 Y"）
  ← 接收：结构化进度报告 + 失败摘要（非截图）

层 1 感知处理器（复眼+视叶，机械，毫秒级，无 LLM）：
  Windows: UIA 可访问性树（元素名/类型/坐标/状态/是否可点）
  浏览器: DOM 树（同理）
  任意窗口: 帧间差 + OCR 兜底
  输出：压缩状态 ≈ 200-500 token 的元素清单 + 相对上帧的差分
  ——这是"果蝇视觉读取信息并转成 LLM 可理解信息"的处理器

层 2 点击 LLM（KC+MBON，快）：
  读压缩状态 → 立即出动作（可流式：先出粗动作再出参数）
  三档分流（果蝇反射阶梯）：
    反射动作：确定模式（点"确定"按钮、关闭弹窗）→ 规则直接执行，0 LLM 调用
    常规决策：glm-5.3-flash 读压缩状态 → 单次短调用出动作+预测声称
    疑难上报：歧义/失败 → 上报慢规划器（这就是"像人一样"：
      人也不是每步都过大脑——脊髓反射、基底节习惯、前额叶规划三层）

层 3 收费站（hallucination_gate，每步）：
  动作必须携带预测声称（"点了 X，预期窗口关闭"）
  UIA 树机械核验（窗口真的关了吗）→ REFUTED 带证据喂回
  ——这就是 P270 harness 在 Windows 域的实例化
```

## 三、可行性判断

**已验证可行的部分**：P270 harness 已实现"动作→声称→机械核验→证据回传"
完整循环（ARC-AGI-3 域，30 步）；渲染层 1 秒级（P272）；帧差提取是纯
numpy（毫秒）。所有组件都有运行代码。

**需要新建的**：
1. Windows UIA 处理器（pywinauto/uiautomation 库，成熟，~1-2 天）
2. 压缩状态格式定义（元素清单+差分的 schema）
3. 动作分流器（反射规则表 + LLM 兜底）
4. DeepSeek 规划器接口（其 API 已有）

**诚实的难点**：
1. UIA 覆盖不齐：自绘界面/游戏无可访问性树——OCR 兜底精度下降；
   自绘界面上"压缩状态"退化为"OCR 文本+像素差"，坐标错位类错误会部分回归
   （P270 教训的残余风险，用渲染坐标轴标注缓解）；
2. 点击 LLM 的冷启动：无训练数据。路径=先用 glm-5.3-flash 读压缩状态起跑，
   全程记录（状态→动作→结果）→ 数据积累后蒸馏出本地小模型（0.6B 级，
   我们的 GPU 可训）——**蒸馏是这条架构独有的免费午餐**：压缩状态比截图
   小 10 倍，训练数据量需求同比例下降；
3. 泛化边界（G6 定律适用）：点击 LLM 对见过的 UI 模式快而准，对全新
   UI 范式不会自发泛化——上报慢规划器是唯一正确路径，不要试图让它聪明。

## 四、token/速度经济学（对比现行 computer use）

| | 现行截图循环 | 本架构 |
|---|---|---|
| 每步输入 | 全屏 ~1-3k token + 长思考数千 token | 压缩状态 200-500 token + 短动作输出 |
| 每步延迟 | 1-5 分钟（flash 档实测） | 反射 0ms / 常规 2-5s / 上报分钟级 |
| 每步可验证性 | 无 | 每步预测声称+机械核验 |
| 规划频率 | 每步都"规划"（浪费） | 慢规划器只在子目标边界介入 |

## 五、首战场景建议（真实自用，非玩具）

候选：ERP 出库流程（多窗口、表单、重复性高——反射档吃掉大半动作）
或面单打印工作流。选择标准：UIA 树覆盖好 + 你有真实耐心收益 +
失败成本可承受。首战目标：单流程端到端 20 步内零人工干预完成一次。

## 六、预注册判据（P281，构建前锁定）

- H-econ：常规决策步骤的输入 token 比截图循环下降 ≥60%；
- H-reflex：反射档覆盖 ≥50% 的动作且零错误；
- H-gate：预测声称经 UIA 核验的精度随证据反馈上升（P270 修复后重测）；
- H-end2end：选定流程 20 步内零人工干预完成。
失败处置：任一判据失败→该组件回退到截图+全推理，如实入册。
